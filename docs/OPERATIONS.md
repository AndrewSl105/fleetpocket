# Operations

Health, metrics, logs, retention and restart behaviour of a running Jungle Monkey. Back to the [README](../README.md); setup is in [DEPLOY.md](DEPLOY.md).


- **Health**: `GET /healthz` checks Postgres and Docker.
- **Metrics** (`GET /metrics`, internal network only): `fleetpocket_tasks{status}`, `fleetpocket_queue_length`, `fleetpocket_run_duration_seconds{project}`, `fleetpocket_cost_usd_total{project}`, `fleetpocket_runner_exits_total{code}`, `fleetpocket_telegram_api_errors_total{op}`, `fleetpocket_github_api_errors_total{op}` (auto-fix adds the ops `list_check_runs` and `job_logs`), `fleetpocket_autofix_attempts_total{project}` (CI auto-fix attempts started), `fleetpocket_autofix_outcomes_total{project,outcome}` (loops that ended: `green`, `needs_you`, `cancelled`), `fleetpocket_mcp_gateway_calls_total{server,outcome}` (MCP gateway tool calls: `ok`, `error`, `denied`, `limit`), `fleetpocket_mcp_gateway_call_seconds{server}` (upstream time), `fleetpocket_egress_blocked_total{project}` (hosts the egress proxy refused, once per host and run), `fleetpocket_budget_held_total{project,scope}` (queued tasks a monthly budget held, scope `global` or `project`), `fleetpocket_budget_alerts_total{scope,level}` (80% and 100% budget notices sent), `fleetpocket_budget_overrides_total{project}` (tasks the owner started despite a budget), `fleetpocket_schedule_firings_total{outcome}` (schedule firings: `started`, `queued`, `skipped`, `missed`, `failed`), `fleetpocket_loops_total{project,state}` (loops that ended: `passed`, `max_iterations`, `budget`, `no_changes`, `stopped`). The budget metrics' `scope` can also be `schedule`. `fleetpocket_cost_usd_total{project}` includes estimated costs of Codex and Cursor runs.
- **Monthly budgets**: a calendar month in the server's time zone (`TZ` of the server container; UTC unless set). A task that waits for a budget stays `queued` with `budget_wait`; raise or remove the cap (Settings → Budgets and prices, or the project form) or tap Start anyway. Running runs are never stopped by a monthly cap.
- **Schedules** (none by default): the server checks every 20 seconds. Times are wall-clock times in each schedule's IANA zone (the zone data is built into the binary, independent of the container's `TZ`). After a restart or downtime each schedule runs at most one late firing, and only if it is less than one interval late; older ones appear as `missed` in its history and on Telegram. Pausing and resuming never makes up missed firings. A schedule's monthly cap holds only its own tasks (`waiting: budget`, scope `schedule`).
- **Loops**: the check command runs inside the task's runner container as the runner user, after the agent's run, with the agent's credentials removed from its environment and a timeout (default 10 minutes). Nothing is pushed between iterations; a loop that stops for any reason pushes once and opens or updates the PR. With checkpoints on, every iteration ends with an `iteration` checkpoint.
- **Logs**: `docker compose -f docker-compose.deploy.yml logs -f server`; JSON (`log/slog`), task lines carry `task_id`, `run_id` and `project`.
- **Retention** (every 10 minutes): agent events of finished tasks older than `EVENT_RETENTION` are deleted (status events stay); workspaces, Claude state volumes and the attachments of failed and cancelled tasks are deleted `WORKSPACE_RETENTION` after a task finishes (a completed task's attachments go right away); attachment files without a task are swept; idle sidecars are removed after `SIDECAR_IDLE_TTL`; expired sessions are purged.
- **Checkpoints** (off by default; Settings → Checkpoints): the runner keeps them as hidden refs `refs/jm/checkpoints/<run>/<n>` in the task workspace, never pushed, so they disappear with the workspace after `WORKSPACE_RETENTION` (restore then shows that reason). They cost a commit object per step that changed files, in the workspace's own object store. A restore of a task on a node needs a node with this server's version (four new wire calls). A push after a restore uses `--force-with-lease` on `agent/<id>…` branches only; if someone else pushed to the branch meanwhile the lease fails and the task fails without overwriting anything.
- **Restart safety**: on startup, running agents are re-attached and missed events replayed from `<workspace>/.fleetpocket/events.jsonl`; exits that happened while the server was down are applied, vanished runs fail with reason `lost`, interrupted preparation is re-queued, interrupted pushes retried, orphaned containers and networks removed.
- **`SECRETS_KEY`**: encrypts MCP server credentials in Postgres (AES-256-GCM). `install.sh` adds it to `.env` on install and on upgrade when missing; it never rotates it. Back it up with the database: a database restored without its key loses the stored MCP credentials (the API then answers `secrets_unreadable`; re-enter them). Without the key the server logs a warning and MCP servers are disabled; everything else works. Local mode keeps its key in the OS keychain (or `secrets.json`, 0600, without one).
- **Sidecars of MCP and egress**: an allowlist project's runs add `fleetpocket-svc-<task>-egress` (the server image running `fleetpocket egress-proxy`, set by `EGRESS_PROXY_IMAGE`) and the network `fleetpocket-egress-<task>`; stdio MCP servers run as `fleetpocket-mcp-<task>-<name>` on `fleetpocket-mcp-<task>` on the server's Docker (npm/pip packages in the agent image; `image` servers are pulled). They carry the task labels, stop with the run (stdio) or the task's sidecars (proxy), and reconciliation removes leftovers. A connection test starts a throwaway `fleetpocket-mcp-test-…` container that removes itself. After a restart the gateway reconnects on the next call; per-run call counts start again.
- **Gateway reachability**: runners call `MCP_GATEWAY_URL` (default `PUBLIC_BASE_URL`) + `/api/mcp-gateway/`, which Caddy already routes with `/api/*`. If the host cannot reach its own public URL (hairpin NAT), set `MCP_GATEWAY_URL` to an address containers can reach. Local mode on Linux: the server listens on loopback, which containers cannot reach, so MCP servers and the allowlist's gateway path need `MCP_GATEWAY_URL` and a listen address containers can reach (Docker Desktop on macOS/Windows works as is).
